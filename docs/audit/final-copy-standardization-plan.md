## How to read this document

- **Current** — the exact wording live today, per applicable surface (surfaces that are hidden,
  N/A for the domain, or have no live notification are omitted from that event's row).
- **Final wording** — the proposed wording per surface. Different audiences may legitimately see
  different, non-identical wording for the same event (Admin/CSV factual; Issuer/Investor
  Activity in second person where natural; Notification titled for outcome clarity) as long as the
  underlying business meaning stays the same and is never misleading.
- **What will happen exactly** — a literal `old → new` line per surface, or `no change`. The
  technical event name is always `no change`.
- **Decision** — one of:
  - **CHANGE** — current wording is misleading, unclear, too technical, or unnecessarily
    inconsistent.
  - **KEEP_DIFFERENT** — different surfaces intentionally use different, non-misleading
    perspectives; current wording is already clear.
  - **MINOR_CLEANUP** — only capitalization, awkward phrasing, or an uncurated fallback label
    needs cleanup; the underlying wording choice is already correct.
  - **NO_CHANGE** — current human-facing wording is already good despite the technical event name,
    or nothing is currently displayed to change (a hidden/excluded surface, which is a visibility
    question and out of scope here).

## Top changes worth implementing

Ranked by user-facing clarity impact, not by count:

1. **`CONTRACT_WITHDRAWN`** — Admin says "Facility Offer Rejected" and the notification says the
   generic "Application Withdrawn" for what is actually the issuer declining the offer. Fix to
   "Facility Offer Declined" everywhere, with a notification message that names the decline.
2. **`INVOICE_OFFER_REJECTED`** — the same decline-vs-reject mismatch as above, for invoices.
3. **`EMAIL_CHANGED`** — "Email changed" is actively misleading; the action is email
   verification, not an address change. Fix to "Email Verified".
4. **`ACTIVATE`** — the investor-facing activity feed currently shows the exact same "Note Active"
   title as the issuer's, instead of an investment-perspective title. Fix to "Your Investment Is
   Active".
5. **`NOTE_DEFAULT_MARKED`** — same investor/issuer title collision as above for the default event;
   fix to "Your Investment Is in Default".
6. **`INVOICE_OFFER_ACCEPTED`** — the CSV export fallback still title-cases the raw technical event
   to "Invoice Offer Accepted", the one surface still showing "Accepted" instead of "Signed".
7. **`AMENDMENTS_SUBMITTED`** — the technical name reads as an issuer submission when it is
   actually CashSouk's request; current copy is split across "Amendment Request Sent" / "Changes
   Requested" with no shared business term. Unify to "Amendment Requested" (Admin/notification) and
   "CashSouk Requested an Amendment" (Issuer).
8. **`CONTRACT_OFFER_RETRACTED`** / **`INVOICE_OFFER_RETRACTED`** — the notification title "Offer
   Updated" does not say what happened. Fix to "Facility/Invoice Offer Retracted".
9. **`onboarding_logs.PROFILE_UPDATED`** / **`access_logs.PROFILE_UPDATED`** — the bare label
   "Profile Updated" collides across three unrelated tables/business meanings in the same admin
   product; disambiguate to "Organization Profile Updated" / "User Profile Updated".
10. **`ONBOARDING_CANCELLED`** — Admin still says "Onboarding Cancelled" for what is actually an
    admin-initiated restart (the issuer/investor copy already correctly says "Restarted"). Align
    Admin/CSV to "Onboarding Restarted".
